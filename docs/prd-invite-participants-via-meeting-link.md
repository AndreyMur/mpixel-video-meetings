# PRD: Invite participants via meeting link

**Дата**: 2026-08-17
**Статус**: Draft

## Цель

Дать организатору возможность отправлять персональные приглашения участникам встречи прямо со страницы встречи. Приглашение — это ссылка на встречу: открывший её зарегистрированный пользователь получает доступ к встрече, и она появляется у него в списке встреч.

## Пользовательские сценарии

- Организатор открывает встречу -> видит строку участников как выпадающий список e-mail
- Организатор нажимает на e-mail участника -> появляется диалог подтверждения отправки приглашения
- Организатор подтверждает отправку -> участнику на e-mail приходит ссылка на встречу
- Организатор отменяет -> ничего не отправляется
- Приглашённый открывает ссылку -> встреча становится доступной и появляется в его списке встреч

## В скоупе

- На странице `meetings/[id]` строка с количеством участников превращается в выпадающий список всех e-mail участников
- При нажатии на e-mail открывается диалог «Отправить приглашение?» с кнопками подтверждения/отмены
- Отправка приглашения только организатором (создателем встречи)
- Приглашение — ссылка на страницу встречи, отправленная по e-mail
- Ссылка работает только для зарегистрированных пользователей: открывший её получает доступ к встрече без дополнительного подтверждения
- Встреча приглашённого появляется в его списке встреч (`GET /meetings`)
- Приглашённый имеет полный доступ к файлам встречи (просмотр и загрузка); редактирование и удаление встречи — только у организатора

## Не в скоупе

- Приглашение пользователей без аккаунта (guest-доступ)
- Автоматическая отправка приглашений при создании/изменении встречи (существующий флоу остаётся без изменений)
- Повторная отправка приглашения уже принявшим его участником
- Отзыв уже выданного доступа
- Уведомления в реальном времени

## Технические ограничения

- Встреча сейчас привязана к `userId` создателя; `participants` — это массив e-mail, а не связанные пользователи. Для выдачи доступа приглашённому потребуется связь между встречей и пользователями (например, таблица доступа или поле участников)
- Ссылка привязана к e-mail: доступ получает только пользователь, чей e-mail совпадает с адресом в `participants`
- Неавторизованный пользователь по ссылке должен пройти регистрацию/вход, и только после этого получить доступ
- SMTP-отправка не гарантирует доставку: отправка приглашения не должна падать при ошибке почты

## Критерии готовности

- [ ] На странице `meetings/[id]` строка «N участников» открывает выпадающий список всех e-mail из `participants`
- [ ] Список участников виден всем, у кого есть доступ к встрече, но отправка приглашения доступна только организатору
- [ ] Нажатие на e-mail показывает диалог подтверждения с кнопками «Отправить» и «Отмена»; «Отмена» ничего не отправляет
- [ ] Подтверждённое приглашение отправляет участнику e-mail со ссылкой на страницу встречи
- [ ] Зарегистрированный пользователь, чей e-mail есть в `participants`, после перехода по ссылке получает доступ к встрече и видит её в своём списке встреч
- [ ] Неавторизованный пользователь по ссылке попадает на вход/регистрацию; после входа под e-mail из `participants` получает доступ к встрече
- [ ] Пользователь, чей e-mail не входит в `participants`, по ссылке не получает доступа
- [ ] Приглашённый может просматривать и загружать файлы встречи; редактировать и удалять встречу может только организатор
- [ ] Ошибка почты при отправке приглашения не ломает страницу (отображается сообщение об ошибке)

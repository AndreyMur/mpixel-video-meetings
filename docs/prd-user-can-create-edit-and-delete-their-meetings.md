# PRD: User can create, edit and delete their meetings

**Дата**: 2026-08-16
**Статус**: Draft

## Цель

Дать пользователю возможность управлять своими встречами: создавать, редактировать и удалять их, задавая название, описание, время и участников. Участники получают email-приглашение, что автоматизирует процесс созыва без ручной коммуникации.

## Пользовательские сценарии

- Пользователь создаёт встречу с названием, описанием, временем и списком участников -> Встреча сохранена, участникам отправлено email-приглашение
- Пользователь редактирует встречу (название, описание, время, участники) -> Изменения сохранены, новые/изменённые участники получают актуальное email-приглашение
- Пользователь открывает список своих встреч -> Видит все свои встречи с актуальными атрибутами
- Пользователь открывает одну свою встречу -> Видит её детали
- Пользователь удаляет свою встречу -> Встреча удалена из списка
- Пользователь удаляет встречу, в которой есть загруженные файлы -> Удаление отклонено с понятным сообщением

## В скоупе

- Создание встречи: название, описание, время, участники (email-адреса)
- Редактирование встречи: изменение любого из атрибутов (название, описание, время, участники)
- Просмотр списка своих встреч и деталей одной встречи
- Удаление встречи
- Отправка email-приглашения участникам при создании и при изменении состава/атрибутов встречи
- Доступ к встречам только их владельца (текущего пользователя)
- Валидация атрибутов: обязательные поля (название, время), корректные email-адреса участников

## Не в скоупе

- Подтверждение/принятие приглашения участником (accept/decline)
- Отмена приглашения при удалении участника из встречи
- Календарная интеграция (Google/Outlook) и напоминания
- Публичные/общие встречи между пользователями системы
- Удаление встречи с файлами — удаление блокируется до удаления файлов вручную
- Повторяющиеся встречи (recurring)

## Технические ограничения

- Встреча не может быть удалена, если у неё есть загруженные файлы (`MeetingFile`) — иначе теряются данные из объектного хранилища
- Email-адреса участников не обязаны быть пользователями системы — приглашение уходит на любой валидный адрес
- Отправка писем требует SMTP-провайдера; конфигурация выносится в окружение
- Встречи скоупируются по владельцу (`userId`) — доступ только к своим

## Критерии готовности

- [ ] Создание встречи: POST-запрос с названием, описанием, временем и участниками сохраняет встречу и возвращает её с id
- [ ] Редактирование встречи: PATCH-запрос обновляет любой из атрибутов встречи; ответ содержит обновлённую встречу
- [ ] Список встреч: GET возвращает только встречи текущего пользователя
- [ ] Детали встречи: GET по id возвращает встречу только её владельцу; для чужой встречи — ошибка доступа/404
- [ ] Удаление встречи: DELETE по id удаляет встречу владельца; для чужой встречи — ошибка доступа/404
- [ ] Удаление встречи с файлами: запрос отклоняется с понятным сообщением; встреча и файлы остаются на месте
- [ ] Валидация: встреча с пустым названием или без времени не создаётся; невалидный email участника отклоняется
- [ ] Приглашения: при создании встречи каждому участнику отправляется email-приглашение
- [ ] Приглашения при редактировании: при изменении состава или атрибутов участникам отправляется актуальное приглашение
- [ ] Все эндпоинты защищены аутентификацией (JWT)

# PRD: Страница профиля и редактирование профиля

**Дата**: 15 августа 2026
**Статус**: Draft

## Цель

Дать пользователю отдельную страницу профиля, где он видит свой email, имя и аватар, и возможность редактировать профиль: менять имя (необязательное display name), загружать новый аватар и менять пароль с подтверждением старого. Аватар и имя отображаются в профиле и в шапке главной страницы вместо текущего email.

## Пользовательские сценарии

- Пользователь открывает страницу профиля -> видит email, имя (или заглушку) и аватар.
- Пользователь меняет имя -> имя сохраняется и обновляется в профиле и в шапке главной страницы.
- Пользователь загружает новый аватар -> аватар обновляется в профиле и в шапке главной страницы.
- Пользователь меняет пароль, введя старый -> пароль обновляется, пользователь остаётся залогиненным.
- Пользователь вводит неверный старый пароль -> смена пароля отклоняется с сообщением об ошибке.
- Пользователь удаляет аватар -> аватар сбрасывается, отображается заглушка.
- Пользователь не залогинен и открывает страницу профиля -> перенаправляется на страницу входа.

## В скоупе

- Страница профиля с отображением email, имени (display name), аватара.
- Страница/форма редактирования профиля: изменение имени, загрузка/удаление аватара, смена пароля (старый + новый).
- Модель данных: поле `name` (необязательное) и `avatarObjectKey` в модели `User`.
- Загрузка аватара в объектное хранилище (S3/MinIO, ключ по пользователю), валидация типа и размера на бэкенде.
- Отдача аватара по ссылке для отображения в UI.
- Отображение аватара и имени в шапке главной страницы вместо email.
- Аутентифицированный доступ: редактировать профиль может только владелец.
- Лимиты: аватар до 5 МБ, изображения (png/jpeg/webp).

## Не в скоупе

- Уникальность или обязательность имени (это необязательный display name).
- Смена email.
- Подтверждение email/пароля по ссылке или коду.
- Разлогинивание сессий после смены пароля.
- Двухфакторная аутентификация.
- Смена аватара в других местах, кроме профиля и шапки главной страницы.
- Ограничение суммарного объёма хранилища аватаров.

## Технические ограничения

- Поля `name` и `avatarObjectKey` отсутствуют в модели `User` — требуется миграция Prisma.
- JWT-токен содержит только `sub` и `email`; после смены имени/аватара данные в токене не обновляются — UI должен подтягивать актуальный профиль с бэкенда (GET /users/me), а не только из токена.
- Аватар хранится в объектном хранилище (S3-совместимое, MinIO); ссылка формируется по защищённому эндпоинту.
- Изображения обрабатываются как есть; ресайз/кроп аватара не входит в фичу.
- Старый пароль проверяется на бэкенде (bcrypt), а не только в UI.

## Критерии готовности

- [ ] Аутентифицированный пользователь может открыть страницу профиля и видит свой email, имя (если задано) и аватар (или заглушку).
- [ ] Пользователь может изменить имя; после сохранения новое имя отображается в профиле и в шапке главной страницы.
- [ ] Пользователь может загрузить аватар до 5 МБ формата png/jpeg/webp; аватар сохраняется в хранилище и отображается в профиле и в шапке главной страницы.
- [ ] Загрузка файла больше 5 МБ или не-изображения отклоняется с понятным сообщением об ошибке.
- [ ] Пользователь может удалить аватар; после удаления отображается заглушка.
- [ ] Пользователь может сменить пароль, введя корректный старый пароль; после смены старый пароль перестаёт работать, а новый — работает при входе, пользователь остаётся залогиненным.
- [ ] Ввод неверного старого пароля отклоняется с понятным сообщением об ошибке, пароль не меняется.
- [ ] Изменять профиль может только владелец; запросы от другого пользователя или без токена возвращают 401/403.
- [ ] Данные профиля подтягиваются с бэкенда через защищённый JWT-эндпоинт и актуальны сразу после сохранения (без перелогина).
- [ ] Страница профиля недоступна без авторизации (редирект на страницу входа).

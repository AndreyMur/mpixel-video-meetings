# Plan: Invite participants via meeting link

**PRD:** docs/prd-invite-participants-via-meeting-link.md
**Дата:** 2026-08-17

## Фазы реализации

### Фаза 1: Backend — выдача доступа приглашённому (Tracer Bullet)

**Цель:** Зарегистрированный пользователь, чей e-mail есть в `participants`, получает доступ к встрече по ссылке, и встреча появляется в его списке. Это минимальный рабочий путь всей фичи.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Добавить в Prisma модель доступа `MeetingAccess` (связь `meetingId` ↔ `userId`) с миграцией БД
- [ ] Изменить `GET /meetings`: возвращать встречи, где пользователь является создателем ИЛИ имеет запись доступа
- [ ] Изменить `GET /meetings/:id`: если e-mail пользователя есть в `participants` и он не создатель — создать запись доступа и вернуть встречу; иначе (нет доступа, e-mail не в `participants`) — 404
- [ ] Распространить проверку доступа на файлы: `GET .../files`, `GET .../files/:id/download` и загрузку файла доступны создателю и приглашённым
- [ ] Написать unit-тесты: выдача доступа по e-mail из `participants`, отказ пользователю вне `participants`, появление встречи в списке после принятия, доступ приглашённого к файлам

**Когда готова:** Приглашённый пользователь, чей e-mail входит в `participants`, открывает ссылку на встречу, видит её и её файлы, и встреча появляется в его списке встреч; пользователь вне `participants` получает 404.

### Фаза 2: Backend — отправка приглашений

**Цель:** Организатор может отправлять участникам e-mail с ссылкой на встречу; ошибка почты не ломает запрос.
**Затрагивает:** backend
**Задачи:**

- [ ] Добавить `POST /meetings/:id/invitations` (только организатор; `{ email }` должен быть в `participants` и не быть e-mail организатора)
- [ ] Добавить конфигурацию адреса фронтенда (`FRONTEND_URL`) и включить ссылку на страницу встречи в шаблон письма (текст и HTML)
- [ ] Отправлять письмо через существующий `EmailService`; ошибки SMTP логировать, не проваливая запрос
- [ ] Запретить отправку приглашения не-организатору (403)
- [ ] Написать unit-тесты: отправка организатором, 403 для приглашённого, валидация e-mail, ссылка в письме, устойчивость к ошибке почты

**Когда готова:** Организатор подтверждает приглашение участнику — на e-mail уходит письмо со ссылкой на встречу; не-организатор не может отправлять; сбой почты возвращает понятную ошибку без падения.

### Фаза 3: Frontend — список участников и отправка приглашений

**Цель:** На странице встречи строка участников превращается в выпадающий список e-mail с диалогом подтверждения отправки.
**Затрагивает:** frontend
**Задачи:**

- [ ] На `meetings/[id]` заменить строку «N участников» на выпадающий список всех e-mail из `participants`
- [ ] При нажатии на e-mail показывать диалог подтверждения «Отправить приглашение?» с кнопками «Отправить» и «Отмена»; отмена ничего не отправляет
- [ ] Подтверждение вызывает `POST /meetings/:id/invitations`; при успехе — уведомление об отправке
- [ ] Показывать кнопку/действие отправки только организатору (для приглашённых — только просмотр списка)
- [ ] Покрыть тестами: открытие списка, диалог подтверждения, отмена, отправка, скрытие отправки у не-организатора, обработка ошибки отправки

**Когда готова:** На странице встречи список участников — выпадающий, отправка приглашения подтверждается диалогом и доступна только организатору; при ошибке почты отображается сообщение без поломки страницы.

### Фаза 4: Frontend — опыт приглашённого

**Цель:** Приглашённый видит встречу в своём списке, открывает её по ссылке и работает с файлами, но не редактирует и не удаляет встречу.
**Затрагивает:** frontend
**Задачи:**

- [ ] Убедиться, что принятые встречи отображаются в списке `meetings-page` (данные приходят из обновлённого `GET /meetings`)
- [ ] На странице `meetings/[id]` скрывать кнопки «Изменить» и «Удалить» для не-организатора
- [ ] Проверить флоу перехода по ссылке: залогиненный приглашённый открывает ссылку и попадает на страницу встречи; неавторизованный попадает на логин, после входа — на встречу
- [ ] Проверить, что приглашённый может просматривать и загружать файлы
- [ ] Покрыть тестами: скрытие кнопок редактирования/удаления у приглашённого, отображение встречи в списке, доступ к загрузке файлов

**Когда готова:** Приглашённый видит встречу в списке и на странице, загружает и просматривает файлы, но не видит кнопок редактирования/удаления; неавторизованный проходит вход и получает доступ к встрече.

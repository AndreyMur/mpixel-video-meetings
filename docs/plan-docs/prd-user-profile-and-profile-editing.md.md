# Plan: Страница профиля и редактирование профиля

**PRD:** docs\prd-user-profile-and-profile-editing.md
**Дата:** 15 августа 2026

## Фазы реализации

### Фаза 1: backend-profile-data

**Цель:** Tracer Bullet — в модели `User` появляются поля `name` и `avatarObjectKey`, и через защищённые JWT-эндпоинты пользователь может читать свой профиль, менять имя и пароль с проверкой старого. После смены пароля сессия сохраняется.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Добавить в Prisma-модель `User` поля `name` (String?) и `avatarObjectKey` (String?) с миграцией.
- [ ] `GET /users/me` (JWT): возвращает email, name, avatarUrl (null, если аватара нет) для текущего пользователя.
- [ ] `PATCH /users/me`: обновление name; пустое значение очищает имя.
- [ ] `PATCH /users/me/password`: смена пароля по {oldPassword, newPassword}; неверный старый пароль → понятная ошибка, пароль не меняется; пользователь остаётся залогиненным.
- [ ] Тесты: юнит-тесты хендлеров (обновление имени, проверка пароля через bcrypt) и e2e (401 без токена, неверный старый пароль, сохранение имени).
      **Когда готова:** аутентифицированный пользователь получает свой профиль через `GET /users/me`, меняет имя и пароль; неверный старый пароль отклоняется; запросы без токена возвращают 401.

### Фаза 2: backend-avatar

**Цель:** Аватар пользователя загружается, отдаётся по ссылке и удаляется; хранится в объектном хранилище (S3/MinIO), тип и размер проверяются на бэкенде.
**Затрагивает:** backend
**Задачи:**

- [ ] `POST /users/me/avatar` (multipart, JWT): сохранение изображения png/jpeg/webp до 5 МБ в объектное хранилище (ключ по пользователю) и обновление `avatarObjectKey`.
- [ ] Отклонение файлов больше 5 МБ (413) и не-изображений (400) с понятным сообщением.
- [ ] Endpoint отдачи аватара по ссылке (стриминг объекта из хранилища; если аватара нет — заглушка/404).
- [ ] `DELETE /users/me/avatar`: удаление объекта из хранилища и очистка `avatarObjectKey`.
- [ ] Тесты: e2e — загрузка валидного аватара, отклонение лимита и формата, отдача по ссылке и удаление, 401 без токена.
      **Когда готова:** пользователь может загрузить аватар до 5 МБ (png/jpeg/webp), получить его по ссылке и удалить; неподходящие файлы отклоняются с понятным сообщением.

### Фаза 3: frontend-profile-page

**Цель:** Страница профиля и форма редактирования: пользователь видит email, имя и аватар (или заглушку), может изменить имя, загрузить/удалить аватар и сменить пароль. Данные подтягиваются с защищённого JWT-эндпоинта и актуальны сразу после сохранения, без перелогина.
**Затрагивает:** frontend
**Задачи:**

- [ ] Страница профиля (клиентская авторизация, редирект на /login без токена): отображение email, имени и аватара (заглушка, если нет) из `GET /api/users/me` через прокси `/api/*`.
- [ ] Форма изменения имени через `PATCH /api/users/me` с обновлением отображения без перезагрузки страницы.
- [ ] Загрузка и удаление аватара через `POST/DELETE /api/users/me/avatar` (multipart через прокси) с клиентской валидацией 5 МБ и форматов, зеркалящей правила бэкенда.
- [ ] Форма смены пароля (старый + новый) через `PATCH /api/users/me/password`; неверный старый пароль — понятная ошибка.
- [ ] Тесты (vitest + Testing Library): рендер профиля, валидация полей, обработка ошибок и обновление данных после сохранения.
      **Когда готова:** страница профиля открывается по прямой ссылке, показывает email/имя/аватар; изменение имени, загрузка/удаление аватара и смена пароля работают сквозным образом и отображаются сразу; без авторизации — редирект на страницу входа.

### Фаза 4: frontend-header-avatar

**Цель:** Аватар и имя текущего пользователя отображаются в шапке главной страницы вместо email и актуализируются после изменения профиля.
**Затрагивает:** frontend
**Задачи:**

- [ ] В шапке главной страницы отображать аватар (или заглушку) и имя вместо текущего email.
- [ ] Подтягивать актуальный профиль с `GET /api/users/me` при загрузке главной страницы (не полагаться на данные из JWT).
- [ ] Ссылка из шапки на страницу профиля.
- [ ] Состояния загрузки и ошибки профиля в шапке.
- [ ] Тесты (vitest + Testing Library): рендер шапки с аватаром/заглушкой и обновление после изменения профиля.
      **Когда готова:** в шапке главной страницы отображаются аватар и имя вместо email; после изменения профиля данные в шапке обновляются без перелогина.

# PRD: Shared video conference for invited meeting participants (core)

**Дата**: 2026-08-20
**Статус**: Draft

## Цель

Дать всем приглашённым участникам встречи (по email в `participants`) возможность подключаться к общей видео конференции встречи. Бэкенд и инфраструктура: LiveKit-сервис, выдача токена комнаты и доступ строго через существующий механизм MeetingAccess.

## Пользовательские сценарии

- Пользователь с доступом к встрече запрашивает токен для конференции -> получает LiveKit-токен для комнаты встречи
- Участник подключается к комнате -> находится в общей конференции с остальными
- Пользователь без доступа запрашивает токен -> получает отказ (403/404)

## В скоупе

- LiveKit-сервис в docker-compose + env (`LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`), образ `livekit/livekit-server`
- Имя комнаты = `meetingId`; комната создаётся LiveKit автоматически при первом подключении (эфемерная)
- Эндпоинт `POST /meetings/:id/conference/token`: возвращает LiveKit-токен только creator-у или пользователям с `MeetingAccess`
- Токен с коротким TTL, identity = `userId`, метаданными (name, email)
- Проверка доступа переиспользует существующую логику get-meeting (creator OR MeetingAccess)
- Конфигурация сервера: одиночный узел, порты 7880/7881 для разработки

## Не в скоупе

- Запись встречи и транскрибация
- Постоянная история конференций в БД (комнаты эфемерны, живут пока есть участники)
- Ограничение числа одновременных участников (дефолт LiveKit)
- TURN-сервер в проде (базовый ICE работает в локальной сети разработки)

## Технические ограничения

- JWT пользователя (NestJS) отделён от LiveKit-JWT; токен LiveKit короткоживущий
- Токен выдаётся только после верификации доступа — комната не должна быть «открытой» без гейта
- LiveKit — новый сервис и зависимость в обоих приложениях (nothing exists today)
- Встречи скоупятся по userId/MeetingAccess; комната публична внутри этой группы

## Критерии готовности

- [ ] В docker-compose поднимается `livekit`; переменные окружения добавлены в `.env.example` обоих приложений
- [ ] `POST /meetings/:id/conference/token` возвращает валидный LiveKit-токен только creator-у и пользователям с MeetingAccess
- [ ] Пользователь без доступа к встрече получает 403/404 и не получает токен
- [ ] Токен подключается к комнате с именем, равным `meetingId`
- [ ] Интеграционные тесты: выдача токена для creator/access-пользователя и отказ для постороннего
- [ ] Линт и формат чистые
